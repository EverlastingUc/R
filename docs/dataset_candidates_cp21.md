# Checkpoint 21 — Dataset candidates awaiting owner approval

No candidate below has been downloaded or used for Phase 05. The project
instructions require owner approval before data is used for training.

## Option A — Project-generated synthetic classification and regression

- **Classification provenance:** Entropy would generate small labeled clusters
  from explicit mathematical rules in a versioned NumPy script and seed.
- **Regression provenance:** Entropy would generate features and targets from
  an explicit formula plus seeded noise, also from a versioned script.
- **License:** No third-party dataset license applies because the values are
  generated by this project. The generator and parameters would be documented.
- **Trade-off:** Fastest and clearest for learning the training pipeline, but
  results would only demonstrate behavior on synthetic tasks.

## Option B — UCI Iris classification and UCI Bike Sharing regression

- **Iris classification provenance:** Fisher's Iris dataset, distributed by
  the UCI Machine Learning Repository; 150 plant samples, four measurements,
  and three classes. UCI lists the license as Creative Commons Attribution 4.0
  International (CC BY 4.0), DOI `10.24432/C56C76`.
- **Bike regression provenance:** Capital Bikeshare hourly/daily rental counts
  from 2011–2012 with weather and calendar attributes; UCI lists 17,389 hourly
  records and the license as CC BY 4.0, DOI `10.24432/C5W894`.
- **Sources:** [UCI Iris](https://archive.ics.uci.edu/dataset/53/iris) and
  [UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset).
- **Attribution:** The project would credit R. A. Fisher for Iris and Hadi
  Fanaee-T for Bike Sharing, and retain the UCI dataset citations and licenses
  in each manifest.
- **Leakage controls:** Iris splits would preserve class representation. Bike
  records would be split by time, and `casual`/`registered` would be excluded
  when predicting `cnt` because they sum to the target.
- **Trade-off:** Uses real data and teaches attribution and time-aware splits;
  the bike task needs extra preprocessing and stricter leakage checks.

## Option C — Proton-I HTML/CSS request-intent dataset

- **Purpose:** Train the first Proton-I component: a small classifier that
  routes beginner HTML/CSS requests to a known task category. This is a
  classification dataset, not a corpus for training a text-generating LLM.
- **Provenance:** Original, project-authored prompts and labels. The proposed
  samples will be written specifically for this repository; no third-party
  question bank, scraped page, or copied code will be used as training data.
- **Initial labels:** HTML explanation, HTML page structure, HTML links/images,
  HTML forms/lists/tables, CSS selectors, CSS colors/typography, CSS box model,
  CSS Flexbox, CSS Grid, responsive CSS, HTML/CSS code request, and out-of-scope
  JavaScript/other request.
- **Split and hygiene:** Proposed stratified train/validation/test split of
  70/15/15. Normalize text and remove exact/near-duplicate prompts before
  splitting so duplicates cannot cross splits. Keep the test split untouched
  until final reporting.
- **Training method:** Bag-of-words features and the repository's existing
  NumPy feedforward network/training components. The classifier predicts
  categories; it does not itself generate HTML or CSS.
- **Third-party sources:** None are needed for this intent-classification
  dataset. The repository currently has no top-level LICENSE file, so the
  project must choose a repository/data reuse license before distributing the
  authored dataset for reuse outside this project.
- **Trade-off:** Directly aligned with Proton-I's first narrow use case and
  feasible on a modest CPU, but it only measures request routing. It cannot
  establish general HTML/CSS coding ability.

### Separate runtime reference lookup (not training data)

For factual HTML/CSS questions, Proton-I can query MDN at request time and
show the result title, short summary, and source link. Retrieved pages and
summaries will not be added to the training dataset or stored as model weights.
MDN states that its documentation is generally CC BY-SA 2.5 or later and
requires attribution to Mozilla Contributors; code samples have separate
licensing notes. The implementation must show the source link and attribution
when it uses MDN material:
[MDN attribution and copyright licensing](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Attrib_copyright_license).

MDN's own engineering article describes its site-search endpoint
(`/api/v1/search`), but this is not presented as a stable, officially
documented public API. Treat it as best-effort only, set a timeout, handle
errors, and fall back to a normal MDN search-page link:
[How MDN's site-search works](https://hacks.mozilla.org/2021/03/how-mdns-site-search-works/).
