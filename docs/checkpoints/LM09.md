# LM09 — Resumable language-model training

## Objective

Allow an Entropy language-model run to stop and continue from its saved training
state without silently restarting its optimizer, learning-rate schedule, data
samplers, or dropout random stream.

## What a version 2 checkpoint stores

- Model architecture and model parameters.
- Optimizer state, including AdamW moment estimates.
- Learning-rate scheduler state.
- Tokenizer metadata and (for prepared corpora) the corpus manifest hash.
- Total target steps, completed optimizer steps, effective batch size, training
  configuration, best observed validation loss, early-stopping counter, and
  evaluation history.
- PyTorch CPU and available CUDA RNG states, plus the three dedicated CPU
  generators used for training-window sampling and train/validation evaluation.

Checkpoint writes use a temporary file followed by an atomic replace. A
checkpoint is written at each evaluation and again when a training invocation
ends. If a process is forcibly terminated between writes, only work since the
last completed checkpoint can be lost.

## Run and resume

Install the optional language-model dependency and prepare a corpus as usual:

```powershell
python -m pip install -e ".[llm]"
entropy-prepare-corpus .\text-data .\prepared-data
```

Start a run with a fixed total schedule, but limit this invocation to a portion
of the optimizer steps:

```powershell
entropy-train .\prepared-data --steps 10000 --max-steps-this-run 1000 --checkpoint .\entropy-model.pt
```

Continue the same run:

```powershell
entropy-train .\prepared-data --steps 10000 --resume --checkpoint .\entropy-model.pt
```

The same total `--steps`, architecture, tokenizer, corpus, seed, optimizer
settings, warmup/cosine schedule, evaluation interval, and early-stopping
settings must be supplied. The CLI defaults are retained between calls; keep
any non-default options identical. The total step count is the target schedule,
not the number of extra steps to run after resuming.

The Python API exposes the same controls:

```python
train_language_model(
    corpus_path,
    steps=10_000,
    checkpoint_path="entropy-model.pt",
    max_steps_per_run=1_000,
)

train_language_model(
    corpus_path,
    steps=10_000,
    checkpoint_path="entropy-model.pt",
    resume_from="entropy-model.pt",
)
```

A version 2 checkpoint can also be loaded by `entropy-generate`. Older version
1 checkpoints remain inference-compatible, but do not contain enough state to
resume a training run.

## Validation

The PyTorch test suite verifies that a four-step run produces the same history
and model parameters whether it runs continuously or is paused after step two
and resumed. It also checks that a checkpoint rejects a changed corpus or
training configuration.

Exact continuation is tested on CPU. CUDA kernels and different hardware or
PyTorch versions may introduce numerical differences, even when RNG state is
restored.

## Scope and limitations

This milestone makes experiments restartable; it does not improve the model's
learned capabilities by itself. It does not provide distributed training,
mixed precision, checkpoint rotation, automatic recovery after a machine
failure, or a trained general-purpose assistant model. Those remain separate
engineering and evaluation milestones.
