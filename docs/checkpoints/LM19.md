# LM19 — Per-layer key/value cache

## Objective

Avoid recomputing every previous token at each autoregressive generation step.
Reuse each Transformer layer's projected attention keys and values while
decoding the next token.

## Compatibility design

The implementation keeps the existing `nn.TransformerEncoderLayer` blocks
and their parameter names. It computes cached attention using the existing
`self_attn.in_proj_weight`, `in_proj_bias`, and `out_proj` parameters.
No model parameters or checkpoint format are added or renamed.

`forward_with_cache(input_ids, past_key_values=None)` returns logits and a
tuple of per-layer key/value tensors. Cache tensors have shape
`(batch, heads, sequence, head_dim)`. The method is inference-only and does not
retain autograd graphs.

## Generation behavior

`generate_stream` prefills the prompt once. While there is room in the
configured context window, it passes only the newly sampled token plus the
previous layer caches into the next forward step.

When the cache has reached `context_length`, generation rebuilds it from the
current sliding context window. This is necessary because the model uses
learned absolute position embeddings: simply dropping the oldest cached key
would leave every retained token at its previous position index.

The public `generate`, `generate_stream`, and chat APIs remain unchanged.

## Validation

Tests compare cached prefill and incremental logits against the original
full-sequence forward pass, verify generated tokens against a reference loop
that recomputes the sliding context, and reject malformed or overlong caches.
Existing checkpoints continue to load because the learned parameter tensors
are unchanged.

## Limitations

This is a simple inference cache, not paged attention or a production serving
engine. It reduces repeated attention computation while the context grows, but
the implementation still concatenates cache tensors and rebuilds the complete
window after it fills. It does not add batching across user requests, cache
quantization, cache eviction policies, or CUDA-specific memory management.
