# LM24 — Rotary Position Embeddings

## Objective

Add an optional RoPE positional encoding mode for the decoder-only Transformer,
while retaining learned absolute position embeddings as the default and
preserving existing checkpoint compatibility.

## Select the mode

The Python API:

```python
from entropy_lm.model import TransformerConfig

config = TransformerConfig(
    position_encoding="rope",
    rope_base=10000.0,
)
```

Both `entropy-train` and `entropy-chat-train` accept:

```powershell
--position-encoding rope --rope-base 10000
```

The default remains `--position-encoding learned`. RoPE requires an even
attention head dimension. `rope_base` must be finite and greater than one.

## Implementation

RoPE is applied to query and key head vectors using their token positions.
Values are not rotated. The implementation uses interleaved even/odd
coordinates and a configurable frequency base.

The same rotation is applied in:

- Full-sequence training and validation forward passes.
- Cached prompt prefill.
- Incremental cached decoding, using the absolute position represented by
  the existing cache length.
- Sliding-window cache rebuilds, where the retained window is re-indexed from
  zero. A uniform position shift preserves RoPE relative offsets inside that
  window.

The Transformer attention and feed-forward weights are unchanged. RoPE models
do not allocate a learned position-embedding table.

## Checkpoint compatibility

Existing checkpoint architecture dictionaries without the new
`position_encoding` and `rope_base` fields continue to load as learned
absolute positions. New learned-mode checkpoints keep the same parameter names
and shapes. Resume validation accepts this legacy metadata only when the
requested architecture is the default learned-position mode. RoPE checkpoints
record their mode and base explicitly.

## Validation

Tests compare full-forward logits with cached prefill and incremental logits
for both position modes, check causal masking, generate beyond a full context
window, validate RoPE dimensions and base values, verify gradient-checkpoint
gradient equivalence, and train/load both pretraining and SFT checkpoints in
RoPE mode. A resume test covers legacy learned-position architecture metadata.

## Limitations

RoPE changes position representation; it does not automatically increase the
configured context length or improve model quality. The attention head
dimension must be even. This implementation uses a fixed base and does not
implement NTK scaling, YaRN, long-context extrapolation calibration, or
position interpolation. Longer context still increases attention compute and
KV-cache memory.
