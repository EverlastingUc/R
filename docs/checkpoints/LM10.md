# LM10 — Held-out language-model evaluation

## Objective

Measure a trained checkpoint against the prepared corpus's untouched test split.
The evaluator is deliberately separate from training: test examples do not
update gradients, choose checkpoints, or influence early stopping.

## Metrics

`entropy-evaluate` reports:

- Number of test documents scored.
- Number of next-token targets scored.
- Mean cross-entropy in nats per token.
- Perplexity, computed as the exponential of mean token cross-entropy.
- Context length and SHA-256 provenance for the checkpoint and corpus manifest.
- The tokenizer fingerprint used for the evaluation.

The evaluator scores each test document independently, appends its EOS token,
and uses rolling context windows. Each next-token target is counted exactly
once. A document boundary is never crossed to form a prediction context.

Perplexity depends on tokenizer choice and corpus composition. Compare runs only
when their test corpus and tokenizer are the same; do not interpret perplexity
as a universal score across different tokenizers.

## Workflow

Prepare the corpus and train as usual:

```powershell
entropy-prepare-corpus .\text-documents .\prepared --tokenizer bpe --seed 42
entropy-train .\prepared --steps 5000 --batch-size 8 --checkpoint .\runs\entropy.pt
```

Evaluate the resulting checkpoint on the held-out test split:

```powershell
entropy-evaluate .\runs\entropy.pt .\prepared
```

The evaluator checks the manifest tokenizer fingerprint, each test record's
fingerprint, token ID ranges, and exact tokenizer compatibility with the
checkpoint. It refuses to evaluate a mismatched checkpoint/corpus pair.

## BPE corpus metadata correction

The prepared-corpus writer now saves BPE metadata in the canonical form used
when computing the manifest fingerprint. The tokenizer loader and prepared
corpus readers retain compatibility with the earlier versioned BPE file shape.
Re-prepare existing BPE datasets when possible so all generated artifacts use
the canonical format.

## Validation

The PyTorch integration test prepares a BPE corpus, trains a small decoder-only
Transformer on its training and validation splits, and evaluates it against
the isolated test split. The non-PyTorch corpus tests verify that tokenizer
metadata written to disk matches the manifest fingerprint.

## Limitations

This is a measurement foundation, not a quality guarantee. A low perplexity
does not establish factuality, instruction following, reasoning, safety, or
dialogue quality. The current model is still a small experimental baseline;
it has not been trained as a general-purpose assistant. Future evaluation
milestones must add task-specific, instruction-following, factuality, and
human-preference assessments.
