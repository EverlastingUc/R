# Checkpoint 04 — Learning Mechanisms

## Objective

Show experimentally how training works and why memorizing training examples
does not guarantee good predictions on new examples.

## Experiment

The script `experiments/memorization_vs_generalization.py` runs two conditions
with NumPy and the same network implementation:

1. **Structured XOR:** Entropy sees labeled examples around the four XOR
   corners. It is scored on new, jittered examples from the same rule.
2. **Random labels:** a wider network sees eight random input/answer pairs. It
   is scored on new inputs with independently random answers. Since those
   answers have no relationship to the inputs, there is no pattern to learn.

Both runs use a fixed seed and settings in
`configs/cp04_memorization_generalization.json`. The script writes the scores,
hardware description, runtime, and configuration hash to a JSON record, and
saves a comparison plot.

## Measured result

| Condition | Train accuracy | Held-out accuracy | Initial loss | Final train loss |
|---|---:|---:|---:|---:|
| Structured XOR | 1.000 | 1.000 | 0.799114 | 0.001167 |
| Random labels | 1.000 | 0.500 | 0.886534 | 0.018448 |

The structured network learned a repeatable rule and applied it to held-out
examples. The wider model fit every random training answer, but its held-out
accuracy was at chance. That is memorization without generalization.

## Limitations

These are small synthetic datasets, not real-world data. The random-label case
is deliberately impossible to generalize; it demonstrates why training
accuracy alone can mislead, but it does not estimate Entropy's performance on
any practical task. The result is one fixed-seed run.
