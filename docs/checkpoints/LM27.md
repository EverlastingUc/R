# LM27 — Conversation Dataset Quality Audit

## Purpose

Provide a non-destructive audit before SFT or preference training. The audit
scans raw UTF-8 JSONL conversations and reports structural problems, exact
duplicates, role distributions, response-length statistics, repeated
assistant messages, and conversations that do not end with an assistant turn.

## Usage

```powershell
entropy-audit-chat-data .\\datasets\\conversations --report .\\reports\\chat-audit.json
```

The command accepts one JSONL file or a directory of JSONL files. It does not
rewrite, filter, or delete source data. The JSON report contains source/line
references and issue descriptions, but never includes conversation text.

Thresholds are diagnostic heuristics, not quality labels:

```powershell
entropy-audit-chat-data .\\datasets\\conversations --short-response-chars 20 --long-response-chars 8000
```

## Interpretation

- Review malformed records and exact duplicates before preparing the SFT split.
- Inspect unusually short or long assistant responses in the source dataset.
- Review repeated assistant messages and turn-order anomalies manually.
- Keep test and validation examples separate from training data.
- Do not treat this audit as a semantic correctness, factuality, safety, or privacy certification.

The audit deliberately avoids a single quality score: response length and turn
structure are useful signals, but cannot establish whether an answer is true,
helpful, or safe.
