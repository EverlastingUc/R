# Checkpoint 09 — Numerical Computing

## Objective

Demonstrate floating-point precision limits and test stable alternatives for
softmax and log-sum-exp.

## What was built

`src/nn/numerics.py` implements stable softmax, stable log-sum-exp, and a
float32/float64 precision example. The stable functions subtract the maximum
input before exponentiating, preserving the final mathematical result while
keeping intermediate exponentials in a safe range.

## How to run it

```powershell
.\.venv\Scripts\python.exe -m experiments.cp09_numerics_demo
.\.venv\Scripts\python.exe -m pytest -q
```

## Evidence

- For logits `[1000, 1001, 999]`, naive exponentiation did not produce finite
  probabilities. Stable softmax returned `[0.24472847, 0.66524096, 0.09003057]`.
- Stable log-sum-exp returned `1001.4076059644444` for the same logits.
- `large + 1 - large` returned `0` in float32 and `1` in float64 for the
  documented example.
- Focused tests: **8 passed**. Full suite: **72 passed**.
- `black .` and `ruff check .` passed after removing one unused import found by
  Ruff.

## Limitations

The precision example illustrates one effect of finite precision; it is not a
complete comparison of all floating-point errors. The stable operations reject
non-finite input values rather than attempting to infer their meaning.
