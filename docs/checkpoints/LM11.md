# LM11 — Conversation data and assistant-only labels

## Objective

Create a reproducible supervised fine-tuning dataset from conversation JSONL
without training the model to reproduce user prompts as assistant output.

## Input format

Each non-empty JSONL line is one conversation:

```json
{"messages":[{"role":"system","content":"Be concise and accurate."},{"role":"user","content":"What is 2 + 2?"},{"role":"assistant","content":"4"}]}
{"messages":[{"role":"user","content":"Explain gravity."},{"role":"assistant","content":"Gravity is the attraction between masses."}]}
```

The current schema accepts `system`, `user`, and `assistant` roles. Each
conversation must contain at least one user message and one assistant message.
Message content must be non-empty UTF-8 text.

## Preparation

```powershell
python -m pip install -e ".[llm]"
entropy-prepare-chat .\chat-jsonl .\chat-prepared --tokenizer bpe --vocab-size 2000 --seed 42
```

The pipeline:
- Reads JSONL files in deterministic path and line order.
- Validates messages and removes exact duplicate conversations before splitting.
- Splits at conversation level to prevent one conversation from appearing in
  multiple partitions.
- Fits BPE only on training conversations.
- Writes a tokenizer fingerprint, SHA-256 conversation provenance, split
  manifest, and train/validation/test JSONL token records.

## Prompt masking

Each prepared record contains parallel `input_ids` and `labels` arrays of
identical length.

The serialized sequence uses `<|system|>`, `<|user|>`, and
`<|assistant|>` role markers and begins with BOS. Prompt tokens (system and
user headers and content) receive the ignore label `-100`. Assistant content
and its EOS token receive their token IDs as labels. This is the target contract
for a response-only causal-language-model objective: the model receives the
whole conversation as context, while the loss is applied only to assistant
responses.

## Validation

Tests verify that prompt tokens are masked, assistant response and EOS tokens
are supervised, duplicate conversations are removed before splitting, BPE is
saved in the same canonical format used by the manifest fingerprint, and
invalid conversations are rejected.

## Scope and next step

LM11 prepares data only. It does not perform gradient updates or fine-tune a
checkpoint. LM12 will add a trainer that consumes these masked labels, skips
all-masked windows, and reports assistant-only validation loss. This checkpoint
also does not add tool-call roles, image/audio inputs, preference optimization,
or safety alignment.
