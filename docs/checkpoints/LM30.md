# LM30 — Context-Preserving Multi-Turn SFT Windows

## Purpose

Improve supervised fine-tuning on long conversations without allowing a training
window boundary to erase all preceding dialogue context.

## Windowing behavior

- Each conversation remains an independent sequence; context never crosses a
  conversation boundary.
- Windows overlap in their input context. The stride is half the configured
  context length (at least one token).
- Each assistant next-token target is assigned to exactly one window.
- Previously visible context tokens remain available to the model but their
  labels are masked in the current window, preventing duplicate loss accounting.
- System and user tokens remain masked by the assistant-only labels produced
  during chat preparation.
- Short final windows are padded with EOS input IDs and ignored target labels.

This is context-preserving windowed teacher-forced SFT, not recurrent state
training: context older than the configured context length is still unavailable.

## Verification

The PyTorch test suite verifies that the number of supervised targets after
window construction exactly equals the number of assistant labels in the
prepared conversation records. Existing checkpoint, resume, and evaluation
paths use the same window loader, so training and held-out test scoring share
the same boundary semantics.

Run:

```powershell
python -m pytest tests/test_lm_chat_training.py -q
```
