# LM22 — Stop sequences for streamed chat

## Objective

Let chat callers stop generation on an exact configured phrase without
printing that phrase, including when it spans multiple decoded token chunks.

## Behavior

The Python chat functions accept `stop_sequences: list[str] | None`. The
terminal command accepts repeatable `--stop` arguments:

```powershell
entropy-chat .\runs\assistant.pt --stop "<|user|>" --stop "\nUser:"
```

The stream wrapper checks for the earliest complete marker. Before a match is
found, it retains only the longest suffix that could still become a configured
marker. All earlier text is emitted immediately. When a marker is completed,
the wrapper discards it and everything after it, then closes the underlying
token stream so generation stops and model execution state is restored.

When the model reaches EOS or the token limit without a complete marker, any
withheld partial marker prefix is emitted as ordinary response text. Empty
markers and non-string values are rejected. With `None` or an empty list,
streaming behavior is unchanged.

The reference-based benchmark accepts the same stop markers and records them
in its generation settings.

## Validation

Tests split a marker across chunks, verify the marker and later text are
withheld, confirm early termination closes the upstream generator, retain
partial marker prefixes when generation ends without a full match, and verify
earliest-marker selection and input validation.

## Limitations

Matching is exact and case-sensitive. It does not normalize Unicode or
whitespace, and it does not add new tokens to the vocabulary. Stop text is
matched after incremental UTF-8 decoding, so a marker may span byte tokens or
BPE tokens. A stop marker that appears in content intentionally ends the
response at its first occurrence.
