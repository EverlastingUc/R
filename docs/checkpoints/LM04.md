# LM04 — Trainable byte-level BPE tokenizer

## Goal

Replace the byte tokenizer's inefficient one-byte-per-token representation with
a deterministic, corpus-trained byte-pair encoding implementation while keeping
the original byte tokenizer intact as a compatibility baseline.

## Implementation

- UTF-8 bytes are the base vocabulary (IDs 0–255).
- IDs 256–257 remain reserved for the legacy byte tokenizer's BOS/EOS contract;
  BPE learned merges start at 258 and its BOS/EOS IDs follow the merge table.
- Pair frequencies are counted over training documents; ties are resolved
  lexicographically for reproducibility.
- Merge application is deterministic and prioritizes the earliest learned pair.
- Tokenizer state is portable JSON with a format version and explicit type.
- Decoding expands merge IDs recursively and supports strict/replace/ignore
  malformed UTF-8 handling.

## Validation

The unit tests cover Unicode round trips, special tokens, compression of repeated
patterns, deterministic training, save/load compatibility, and invalid inputs.

## Limitations

This is a compact reference BPE implementation, not a production tokenizer.
Training currently uses in-memory Python sequences and repeated full pair counts;
large corpora require a more efficient implementation. The language-model
training loop still uses the byte tokenizer. Wiring BPE into model training,
checkpoint metadata, and inference is the next integration checkpoint.
