# LM14 — Assistant-only held-out evaluation

## Objective

Evaluate an instruction-tuned Entropy checkpoint against the isolated test
partition produced by LM11. Unlike LM10's plain-text evaluator, this metric
scores only the assistant response labels and ignores system and user prompt
tokens.

## Workflow

```powershell
entropy-prepare-chat .\conversation-data .\chat-prepared --tokenizer bpe --vocab-size 2000 --seed 42
entropy-chat-train .\chat-prepared --steps 3000 --checkpoint .\runs\assistant.pt
entropy-evaluate-chat .\runs\assistant.pt .\chat-prepared
```

The evaluator requires a checkpoint marked as
`assistant-response-supervised-finetuning`, verifies the checkpoint tokenizer
against the prepared corpus tokenizer, validates the test record fingerprints
and label alignment, and scores only the test split. The test split is never
used for training or early stopping.

## Reported metrics

- Number of fixed-length windows scored.
- Number of assistant next-token targets scored.
- Assistant-only cross-entropy in nats per token.
- Assistant-only perplexity.
- Model context length.
- Checkpoint and corpus-manifest SHA-256 values.
- Tokenizer fingerprint.

Cross-entropy is accumulated as a token-weighted average across evaluation
batches. Perplexity is the exponential of assistant-only mean cross-entropy.
Compare it only across models using the same conversation test split and
tokenizer.

## Training objective correction

The SFT trainer's gradient accumulation now sums assistant-only token losses
across all microbatches and divides by the total number of supervised assistant
targets in the accumulated batch. This avoids weighting a microbatch with only
a few assistant targets as heavily as a microbatch with many assistant targets.

## Validation

PyTorch tests train a small SFT checkpoint and evaluate it on a held-out chat
test split. They check the reported target count against the prepared split's
assistant-label count, ensure metrics are finite, and reject checkpoints that
are not marked as assistant-only SFT models.

## Limitations

Perplexity is a diagnostic metric, not a complete assistant benchmark. It does
not evaluate instruction correctness, factuality, reasoning, helpfulness,
calibration, toxicity, prompt injection resistance, or human preference.
Meaningful capability claims require curated and sufficiently large held-out
datasets plus task-level and human evaluations.
