# LM15 — Resumable assistant supervised fine-tuning

## Objective

Allow a long assistant fine-tuning run to be paused and continued without
reinitializing weights, AdamW moments, learning-rate schedule, sampled-window
generator, dropout RNG, or validation/early-stopping progress.

## Run in chunks

Start a 3,000-step schedule but execute only the first 500 optimizer steps:

```powershell
entropy-chat-train .\chat-prepared --steps 3000 --max-steps-this-run 500 --batch-size 8 --gradient-accumulation-steps 4 --checkpoint .\runs\assistant.pt
```

Continue the same schedule from that checkpoint:

```powershell
entropy-chat-train .\chat-prepared --steps 3000 --resume --batch-size 8 --gradient-accumulation-steps 4 --checkpoint .\runs\assistant.pt
```

The total `--steps` is the original target, not the number of additional steps.
When resuming, retain the same dataset, architecture, tokenizer, context length,
batch size, gradient accumulation, learning rate, warmup, evaluation interval,
early-stopping setting, seed, and device. `--max-steps-this-run` may change
between invocations because it only controls where the current process pauses.

## Checkpoint structure

The inference-facing `model_state` is the best observed validation model. The
separate `resume_state` stores the latest training weights, optimizer state,
scheduler state, and random-number-generator states. Training metadata records
the total target steps, completed steps, run configuration, corpus manifest
hash, validation history, best validation loss, and early-stopping counter.

This separation matters: resuming continues from the latest step, while
`entropy-chat` and `entropy-evaluate-chat` load the best validation weights.

The checkpoint is written atomically at validation points and whenever a
training invocation ends. A forced termination between saves can lose work
after the last checkpoint, but cannot leave a partially written checkpoint.

## Determinism and compatibility

The PyTorch CPU test compares a continuous four-step run with a run paused
after step one (before the first scheduled evaluation) and then resumed. It
checks identical validation history and exact final best/latest model weights.
The checkpoint also validates its architecture, tokenizer, corpus fingerprint,
and full training configuration before restoring state.

Exact continuation is tested on CPU. Different hardware, CUDA kernels, or
PyTorch versions can introduce numerical differences. Earlier LM12 SFT
checkpoints remain inference-compatible but do not contain the state required
for resuming.

## Scope

LM15 makes assistant fine-tuning restartable. It does not add distributed
training, mixed precision, gradient checkpointing, data packing, dynamic
batching, or checkpoint rotation. It does not itself improve model quality;
that depends on the size, provenance, and quality of training conversations.
