# LM20 — Memory-efficient training controls

## Objective

Offer optional activation recomputation and mixed-precision arithmetic for
pretraining and assistant supervised fine-tuning, without changing model
weights, checkpoint architecture, or the default FP32 behavior.

## Training options

Both `entropy-train` and `entropy-chat-train` accept:

- `--precision fp32` (default): full precision; no autocast or loss scaling.
- `--precision bf16`: BF16 autocast on CPU or CUDA.
- `--precision fp16`: CUDA-only FP16 autocast with dynamic gradient scaling.
- `--gradient-checkpointing`: recompute Transformer layer activations during
  backward rather than retaining every layer's activations.

The same options are available in the Python APIs as `precision` and
`gradient_checkpointing`.

## Resume behavior

The scaler state is stored in the pretraining checkpoint and in the SFT
`resume_state`. Resume validates precision and activation-checkpointing
settings against the original run. Older FP32 checkpoints without these
settings remain resumable when the new options are left at their defaults.
FP16 resume requires a checkpoint containing its dynamic loss-scaler state.

The learning-rate scheduler advances only when the scaler does not skip an
optimizer update because of non-finite gradients.

## Validation

The optional PyTorch CI tests compare normal and activation-checkpointed
parameter gradients, exercise BF16 pretraining and SFT on CPU, and verify that
the scaler state is saved. CPU tests also confirm that FP16 is rejected rather
than silently attempting an unsupported device configuration. Existing exact
resume tests run with activation checkpointing enabled.

## Limitations

BF16/FP16 performance depends on hardware. BF16 is generally preferred where
the accelerator supports it; FP16 uses dynamic loss scaling. The CPU BF16 path
is a correctness exercise, not a performance recommendation. Activation
checkpointing reduces activation memory at the cost of additional compute.
This milestone does not add distributed training, optimizer sharding, data
packing, gradient accumulation changes, or hardware benchmarking.
