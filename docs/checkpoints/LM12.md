# LM12 — Assistant-only supervised fine-tuning

## Objective

Train the decoder-only Transformer on prepared conversations while applying
cross-entropy only to assistant response tokens. System and user content remain
available as causal context but do not contribute directly to the loss.

## Workflow

Prepare conversations using the LM11 JSONL schema:

```powershell
entropy-prepare-chat .\conversation-data .\chat-prepared --tokenizer bpe --vocab-size 2000 --seed 42
```

Train a small assistant checkpoint:

```powershell
entropy-chat-train .\chat-prepared --steps 3000 --batch-size 8 --gradient-accumulation-steps 4 --context-length 256 --embedding-dim 128 --heads 4 --layers 4 --checkpoint .\runs\assistant.pt
```

Install the optional PyTorch dependency before using these commands:

```powershell
python -m pip install -e ".[llm]"
```

The trainer loads and validates the tokenizer fingerprint, manifest metadata,
conversation records, token ID ranges, and alignment between input IDs and
labels. It builds fixed-length next-token windows while preserving conversation
boundaries. Windows without assistant targets are skipped. The final partial
window is padded with EOS inputs and ignored labels.

## Loss contract

The causal model now accepts an `ignore_index` for targets. For chat
fine-tuning, that value is `-100`. The trainer shifts each record's labels by
one token against its input window, so the model predicts the next token. User
and system prompt targets are ignored; assistant response and EOS targets are
scored. Validation cross-entropy is aggregated only over non-masked assistant
targets, weighted by the number of targets rather than by the number of
windows.

The model rejects batches that contain no supervised targets. The data loader
rejects misaligned labels, invalid token IDs, stale fingerprints, and splits
without any valid supervised windows.

## Checkpoints

The best observed validation checkpoint is saved in the same version 2 format
that the normal inference loader understands. It stores architecture, model
weights, tokenizer metadata, training task, number of completed steps, history,
and corpus-manifest SHA-256 provenance. The checkpoint can therefore be loaded
with `entropy-generate` or the Python `load_model_checkpoint` function.

LM15 adds interrupted/resumed SFT runs with restoration of model weights,
optimizer and scheduler state, training progress, early-stopping state, and
random-number-generator state. The version 2 checkpoint preserves the best
validation model for inference separately from the latest state used to resume.
Exact continuation is tested on CPU; see [LM15](LM15.md). Gradient checkpointing,
mixed precision, distributed training, sequence packing, and dynamic batching
remain out of scope.

## Validation

The optional PyTorch tests prepare a synthetic byte-token chat corpus, verify
that only assistant labels enter the training windows, run a short SFT
experiment, load the produced checkpoint through the inference loader, and
reject corrupted label alignment.

## Limits

This is the first supervised fine-tuning implementation, not a trained
assistant release. The synthetic tests validate the pipeline only. No claim is
made about instruction-following quality, factual accuracy, safety, dialogue
coherence, or equivalence to ChatGPT. Those require large, curated datasets and
separate evaluation.
