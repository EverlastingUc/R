# LM08 — Prepared corpus training integration

## Goal

Connect the deterministic LM06 corpus-preparation output directly to the
PyTorch language-model trainer, without re-tokenizing the original documents or
fitting a second tokenizer.

## Implemented

- The Python training API accepts either a UTF-8 text string, a text-file path,
  or an LM06 prepared-corpus directory.
- Prepared-corpus loading reads train.jsonl and validation.jsonl, reuses the
  exact tokenizer metadata and merge table, and checks the tokenizer
  fingerprint against both the manifest and every data record.
- Token IDs are range-checked against the reconstructed tokenizer vocabulary.
- Each document receives an EOS boundary when its token stream is assembled,
  preventing next-token windows from silently crossing document boundaries.
- Checkpoint provenance records the SHA-256 of the prepared manifest.
- The entropy-train CLI accepts a prepared-corpus directory as its input.

## Workflow

    entropy-prepare-corpus ./text-documents ./prepared --tokenizer bpe --seed 42
    entropy-train ./prepared --steps 5000 --batch-size 8 --gradient-accumulation-steps 4 --checkpoint ./runs/entropy.pt

The trainer uses the prepared training and validation splits. The test split
remains untouched for final evaluation and is not used for gradient updates or
checkpoint selection.

## Validation

Tests cover successful training from a prepared byte-token corpus and rejection
of stale tokenizer fingerprints. Existing plain-text training remains
supported.

## Limitations

The current trainer concatenates tokenized documents with EOS boundaries and
samples contiguous context windows. It does not yet implement packed sequence
attention masks, weighted document sampling, or distributed training. LM09 adds
resumable training; [LM10](LM10.md) adds a separate held-out test-set evaluator.
Prepared BPE tokenizer files now use the manifest's canonical metadata shape,
and the tokenizer loader remains compatible with the earlier versioned format.
