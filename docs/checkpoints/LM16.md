# LM16 — UTF-8-safe token streaming

## Objective

Expose generated tokens as soon as they are sampled, so local chat does not
have to wait for the entire response before showing anything. Preserve the
existing complete-sequence generation API and complete-response chat function.

## Model API

`CausalLanguageModel.generate_stream(...)` yields one tensor with shape
`(batch, 1)` per decoding step. It uses the same temperature, top-k, EOS,
validation, and model-mode restoration behavior as `generate(...)`.

The existing `generate(...)` method now collects this stream and returns the
same full-sequence tensor as before.

## Chat API and CLI

The Python API:

```python
from entropy_lm.chat_inference import stream_chat_response

for text_chunk in stream_chat_response(model, messages):
    print(text_chunk, end="", flush=True)
```

The `entropy-chat` CLI streams assistant text by default. Use `--no-stream`
to wait for the complete response before printing it.

The stream decodes raw bytes incrementally. This matters for UTF-8 because one
Unicode character may span multiple byte-token IDs or a BPE merge token. The
incremental decoder buffers incomplete sequences and emits a character only
when its bytes are complete. EOS stops the response and is not printed.

## Validation

The optional PyTorch test suite checks that concatenating streamed model tokens
reconstructs the same sequence as `generate`, that the model's original
training/evaluation mode is restored, and that both byte and BPE tokenizers
stream multi-byte Unicode text without replacement-character corruption.

## Limitations

Streaming reduces perceived latency; it does not increase model quality or
tokens-per-second. The current implementation samples autoregressively and
recomputes the model context at each step; KV caching and batched streaming
chat clients are future performance work. The terminal CLI is still a
single-user local interface.
