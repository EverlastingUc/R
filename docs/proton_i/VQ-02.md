# VQ-02 — Number-system operations

## Status

*Implemented (core, partial).* The number-system extension is available in the Valence deterministic mathematics engine and as a model-callable `calculate_expression` tool. It does not yet provide a complete number theory or logarithm/exponential system.

## Supported operations

| Operation | Syntax | Behaviour |
|---|---|---|
| Integer powers | `a ** n` | Integer exponents only; right-associative; exponent magnitude capped at 1,000 |
| Modulo | `a % b` | Exact integer operands only; divisor must be nonzero |
| Absolute value | `abs(x)` | Exact for rational inputs |
| Greatest common divisor | `gcd(a, b)` | Integer operands only |
| Least common multiple | `lcm(a, b)` | Integer operands only |
| Square root | `sqrt(x)` | Exact Fraction when numerator and denominator are perfect squares; otherwise a Decimal approximation for nonnegative real input |
| Ratio | `ratio(a, b)` | Exact rational division; denominator must be nonzero |
| Percentage | `percent(p)` | Returns the rational fraction (p/100) |
| Percentage of a value | `percent(p, x)` | Returns (p/100 	imes x) |

Basic (+), (-), (	imes), and (div), unary signs, parentheses, and decimal literals continue to use exact rational arithmetic wherever possible.

## Exact versus approximate results

- Integer and rational operations return reduced exact fractions or integers.
- A square root such as `sqrt(81/100)` returns exactly `9/10`.
- An irrational root such as `sqrt(2)` returns a bounded-precision Decimal, sets `exact_result` to null, and marks the user-facing answer with `≈`.
- Approximate values stay approximate through later arithmetic rather than being silently relabeled exact.

## Parser and resource boundaries

- Input length: 512 characters
- Token count: 128
- Parenthesis/function nesting: 32
- Numeric literal length: 128 digits
- Exact result size: 384 digits
- Integer exponent magnitude: 1,000
- Only the explicit function whitelist is accepted. Unknown identifiers, attributes, imports, arbitrary Python calls, semicolons, and source execution syntax are rejected.
- Modulo/GCD/LCM reject non-integer arguments. Negative real square roots and zero denominators are explicit errors.

No Python `eval()` or `exec()` is used.

## Model and chat integration

The default CLI/API runtime registers the deterministic calculator tool. The local model may request it through the bounded Ollama tool-call loop; Valence validates the call and returns the exact/approximate result to the model. Direct arithmetic and recognized function/power prompts are answered by the deterministic math engine before model inference.

Website search remains separate and opt-in with `--enable-web-search`.
